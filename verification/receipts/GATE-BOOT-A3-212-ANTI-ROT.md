# GATE BOOT-A3-212 — the fixture can no longer rot silently

**A3-211's closing limit was that the contract fixture is a committed binary artifact that rots whenever A4's source moves — which is
exactly what happened over ten turns. The gate now carries a provenance sidecar and refuses to report a verdict when the tree it is
pointed at disagrees with the blob the fixture was built from.**

Seed blob `f8f476198f`. Fixture provenance: revision `f6cf9caf`, blob `e3109cabff`, recipe `8DABC969D5B21C40`, fixture
`C03F761A7A72CF8F`.

## Behaviour

```
PEPIN_CA_ROOT=<matching tree>   CONTRACT[published]: 14/14 match        exit 0
PEPIN_CA_ROOT=<stale tree>      STALE: … built from blob e3109cabff
                                but the tree's compiler_a.pep is ca732536d5
                                → no verdict, exit 3          (runner: SKIP, never a pass)
no PEPIN_CA_ROOT                fixture used as-is, no staleness claim  exit 0
```

An exit of 3 becomes a **skip**, per the convention set at A3-168: a gate that cannot measure the thing it claims to measure must not
report a pass. In the suite this turns a silent false pass into an explicit `1 skipped`.

## Three of my own errors while building it

1. **`json` was not imported.** My new code called `json.loads` and the `except Exception` swallowed the `NameError`, so the check
   silently did nothing. The `except` now prints. A silent fallback in a verification tool is worse than a crash.
2. **`SOURCE_REL` did not exist** in this file — I assumed a constant from `gate_candidate_171.py`. Two more failed edits before I
   read the file's constants instead of guessing.
3. **`$LASTEXITCODE` read 0 when the gate actually exited 3**, because `Select-Object -First N` terminates the upstream process and
   leaves the variable holding the previous command's value. The exit code I first reported was not the exit code.

None of these changed a conclusion, but the third is the most dangerous kind: **a check whose own return value was mismeasured** while
checking whether the gate measures the right thing.

## Why a skip rather than a warning

A warning scrolls past. The failure this prevents is a gate that prints `14/14 match` against an artifact nobody is shipping — which
is precisely what I reported from A3-198 to A3-211. A gate in that state should be visibly not-running, not quietly green.

## Limits

- The check only fires when `PEPIN_CA_ROOT` is set. With it unset the fixture is used as-is, which is the existing behaviour and
  still can rot — but at least it makes no claim about a tree.
- Blob comparison is over `compiler_a.pep` only; changes to the driver recipe do not invalidate the fixture, though the recipe hash is
  recorded for a reader.
- The fixture still has to be regenerated by hand (A3-211 records how). A gate that rebuilt from source would not need this at all,
  and I have not built one.
